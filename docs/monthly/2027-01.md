把 L2 从切片里的几十行手写基线换成独立包：季节性基线、单侧上界、连续超限期数与四级信号，阈值随项目走。

## 目标

1. **口径可解释**：每个信号都能回答「跟什么比、比了几期、超了几倍」。
2. **不给自己投票**：回溯评估时基线只用更早年份的同期数据，本期不进自己的基线。
3. **阈值可配置**：分级规则存 JSON 随项目版本管理，换病种改文件、不改包。

## 交付

- `epi-alert/`：11 个导出函数、12 篇 Rd 文档、包内默认规则 JSON、86 项断言。
- `alert_demo/run_alert.R`：合成 31 地区 × 36 月 → 注入 3 期暴发 → 回溯与当期各评估一遍 → 预警单与指标 JSON。
- 主仓：L2 改指向 `epiAlert`；切片 `vertical_slice/run_e2e.R` 改用 `alert_counts()`；新增 `alert_l2` 编排阶段与站点入口。

## 设计决定

- **历史只用评估期之前**：季节 / 合并 / 泊松三种方法只取 `cycle` 严格更小的观测；同一年内相邻期不进基线。滑动均值是时间序列口径，取紧邻的最近 `window` 期——两种口径在文档里分开写清楚，不含糊成一句「用历史数据」。
- **不复制上游**：本层只读契约，不改列、不回写；周期编号与 `epiCore::epi_period()` 同口径，两个包对同一份数据算出同样的期号。
- **默认方法随粒度走**：周 / 月 / 季用 `seasonal`，年度用 `pooled`。年度数据没有周期可分，硬套季节窗口只会得到一堆空基线。
- **分级规则是数据**：`alert_rules()` 构造、`alert_rules_write()` 落 JSON，校验不合格直接报错，不静默修正。
- **零依赖**：`Imports` 只有 `stats` / `utils`，不引 forecast、surveillance 或任何建模包。

## 已知限制

- 只做单侧升高检测，下降或双向异常不在本层范围。
- 连续超限期数按整段长度记录：回溯看一段暴发时每期都显示该段总长，当期报表（`assess = "latest"`）看到的才是「已连续几期」。
- 报告延迟、补报会让最近一两期偏低，本层不做数据完整性校正，需要在 L1 质控或上游解决。
- `k` 与分级阈值是默认值，不同病种与报告制度必须自行校准；结果不能直接当公共卫生决策依据。
- 小计数（个位数）下对数正态上界偏松，建议改用 `poisson` 方法。
