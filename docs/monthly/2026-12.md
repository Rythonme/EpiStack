## 1. 本月目标

> **一句话**：把 L1 从「`read_counts()` 顺带做个质控」升级成一个**能对付真实脏数据源**的接入层——多源读取、规则化质控、可审计血统、按需脱敏——但输出的仍然是 `epiCore` 的同一份契约，下游一行不改。

11 月的 L1 只是 `read_counts()` 内置的 `epi_qc()`：能处理重复、缺失、人口分母，但换一个 Excel 表、一个数据库导出、一个 API 分页，就得自己在脚本里写胶水。真实场景里 80% 的时间恰恰耗在这一步。

本月要解决的三件事：

1. **来源异构**：CSV / TSV / 分隔符变体 / Excel / 数据库 / 只读 API / 栅格协变量，用同一套「数据源描述」表达，不写一次性脚本。
2. **质控不可解释**：现在只能看到「剔除 2 行」，看不到「哪条规则、哪一行、为什么」。本月起每次接入都产出**可转发给数据提供方的质控单**（HTML/CSV）+ 机器可读血统（JSON）。
3. **脱敏靠手工**：对外分享或做演示时，地区、日期、小样本都要处理。本月把脱敏变成一个有测试的函数，而不是临时改代码。

### 本月不做（范围控制）

- **不做调度与增量同步**：定时重跑、断点续传、增量拉取属于 L6（2027-08 `epi-flow`）。
- **不做数据仓库建模**：不搞星型模型、SCD、宽表汇总，L1 只负责「脏源 → 干净长表」。
- **不强制引入任何第三方包**：Excel / DB / API / 栅格全部放 `Suggests`，核心链路在只装 base R 的机器上仍要跑通。
- **不接需要密钥的真实 API**：只做通用只读 HTTP 适配器，测试用本地 mock 与公开合成响应。
- **不碰任何真实监测数据入库**：夹具、示例、CI 全部使用合成数据。

### 2.1 接口草案（本月实现以 `man/` 为准）

```r
library(epiIngest)

# 1) 声明来源（异构源用同一个对象表达）
src <- ingest_source(
  type      = "csv",                  # csv / tsv / delim / excel / db / api / raster
  path      = "data/raw_counts.csv",
  encoding  = "auto",                 # 自动探测 UTF-8 / GBK + BOM
  mapping   = list(date = "报告日期", region = "省份",
                   count = "发病数", population = "人口数")
)

# 2) 先看再读：列类型、缺失率、日期范围、重复键、编码判断
ingest_profile(src)

# 3) 规则化质控（规则是数据，可存 JSON 随项目走）
rules <- qc_rules(
  required   = c("date", "region", "count"),
  unique_key = c("date", "region", "disease"),
  range      = list(count = c(0, 1e6)),
  date_seq   = list(by = "month", allow_gap = 1),
  outlier    = list(method = "mad", k = 6)
)
res <- qc_apply(ingest_read(src), rules)
qc_report(res, file = "质控单.html")     # 可转发给数据提供方
ingest_lineage(res, file = "lineage.json")

# 4) 一站式：源 → 质控 → 契约（下游零改动）
core <- ingest_counts(src, rules = rules, time_step = "month",
                      geo = my_geo, graph = "provinces.graph")
validate_contract(core)                  # 仍是 epiCore 的契约

# 5) 对外分享前脱敏
safe <- ingest_desensitize(core, region = "hash", min_count = 5, date = "month")

# 6) 我这台机器上哪些适配器能用
epi_ingest_capabilities()
```

### 2.2 适配器矩阵

| 来源 | 核心（base R） | 可选增强（`Suggests`） | 无包时的行为 |
|---|---|---|---|
| CSV / TSV / 分隔符 | ✅ `read.csv` + 嗅探 | `data.table::fread`（大文件加速） | 正常 |
| Excel `.xlsx/.xls` | — | `readxl`（首选）、`openxlsx` | 明确报错 + 安装提示 |
| 数据库 | — | `DBI` + 驱动（示例 `RSQLite`） | 明确报错 + 列出可用驱动 |
| 只读 API | 基础 `url()`/`download.file` | `jsonlite` + `httr2`（分页 / 重试 / 限速） | 降级为「单次 GET + 无 JSON 解析」或明确报错 |
| 栅格协变量 | — | `terra`（extract）、`exactextractr`（面积加权） | 明确报错 + 安装提示 |

> 原则：**缺包可以少一条路，但不能悄悄少**。`epi_ingest_capabilities()` 必须如实报告。

### 2.3 接口可行性验证（2026-11-13，可安装原型）

正式建包前，先用一个**能安装、能运行的最小包**（`epiIngest 0.0.1`，仅本地验证、不入库）跑通接口主链路，确认草案不是纸面设计：

```
R CMD INSTALL  ->  DONE (epiIngest)
25 PASS / 0 FAIL
```

验证覆盖：UTF-8 BOM + 中文列名、GBK + 分号、UTF-8 + 制表符、多文件目录合并、读取画像、8 类规则（必填 / 唯一键 / 范围 / 未来日期 / 断档 / 地区码 / MAD 异常值 / 跨字段）、`ingest_counts()` 返回 `epi_contract`、与 `epiCore::read_counts()` **逐位一致**、人口缺失由 `geo` 回填、剔除留痕进入对象。

三个只有真写代码才会暴露的问题，已转为 W1 的注意事项：

| 问题 | 结论 |
|---|---|
| `paste0(character(0), "-01-01")` 会回收成长度 1 的 `"-01-01"` | 空索引分支必须 `if (any(idx))` 守卫，否则日期列一旦全为完整日期就莫名报错 |
| `readLines(path, encoding = "GBK")` 传路径时分隔符探测失效 | 必须显式开 `file(path, "r", encoding = enc)` 连接，否则中文 Windows 上永远退回逗号 |
| 用「读取后是否出现替换字符」判断 UTF-8 不可靠 | 改用 `validUTF8()` 判字节序列，GBK 与 UTF-8 一次分清 |

结论：核心函数的签名与返回结构可落地，正式实现按此接口进入 W1；`epi_contract` 的输出路径不变。

## 5. 风险与预案

| 风险 | 预案 |
|---|---|
| L1 换实现后质控口径漂移，golden 被迫更新 | 先写**等价性测试**：新旧实现对同一输入必须同输出；只有确认口径改进才允许动基线，并在 CHANGELOG 写明原因 |
| `Suggests` 适配器在 CI 覆盖不到 | 每个适配器 skip-if-not-installed + 一个本地可跑夹具；CI 增加一个装轻量包（`jsonlite`/`RSQLite`）的 job，重包（`terra`/`readxl`）只在本地矩阵验证 |
| 栅格 zonal stats 需要真实边界，触及隐私 | 全部用 `demo/` 合成格网 + 合成栅格（固定种子），真实边界只在本机、不入库 |
| 编码/分隔符嗅探在脏文件上翻车 | 建 `tests/fixtures/` 脏数据家族：BOM、GBK、混合分隔符、空列、合并单元格导出、CRLF；每个都进单测 |
| 包体膨胀、依赖偷偷变强制 | `DESCRIPTION` 的 `Imports` 只允许 `utils`/`stats`；CI 加一条「只装 base R 跑核心链路」的检查 |

## 6. 已知边界 / 未决事项

- 数据库适配器只承诺「给连接 + 查询」的通用路径，不内置任何厂商驱动。
- API 适配器不做鉴权托管（不存 token），需要鉴权的源由调用方自行提供已签名的请求函数。
- 栅格协变量本期只做「按面聚合」（zonal），不做格网重采样、投影转换与遥感指数计算（留给 2027-09 `epi-geoai`）。
- 脱敏只覆盖地区 / 日期 / 小样本三个维度，不做差分隐私。
