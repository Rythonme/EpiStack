# 2026-12 · `epiIngest` 数据接入层

把 L1 从「`read_counts()` 顺带做质控」换成独立的接入层：多源读取、规则化质控、可追溯血缘、按需脱敏，输出仍是同一份契约。

| 项 | 内容 |
|---|---|
| 版本 | `v0.2.0` |
| 包 | `epiIngest` 0.2.0 |
| 层 | L1 多源接入与质控 |

## 目标

1. **来源异构**：CSV / Excel / 数据库 / 只读接口 / 栅格协变量用同一套「数据源描述」表达，不用为每个来源写一次性脚本。
2. **质控可解释**：说明哪条规则、哪一行、为什么被标记，产出能直接转给数据提供方的质控单。
3. **脱敏成函数**：对外分享前对地区、日期、小样本做处理，而不是临时改代码。

## 交付

- `epi-ingest/`：16 个导出函数、16 篇 Rd 文档、包内默认规则 JSON、96 项断言。
- `ingest_demo/run_ingest.R`：合成 31 地区 × 36 月 → 注入脏数据 → 质控单 → 契约比对 → 血缘 JSON。
- 主仓：L1 改指向 `epiIngest`；切片 `vertical_slice/run_e2e.R` 改用 `ingest_counts()`。

## 设计决定

- **不引强制依赖**：`Imports` 只有 `utils` / `stats` / `tools`，Excel、数据库、栅格、哈希后端全在 `Suggests`，缺包时报出安装提示而不是静默降级。
- **规则是数据**：质控规则存 JSON，随项目做版本管理，换口径改文件不改包；`error` 与 `warn` 两级处置，warn 的全局行为可切换。
- **契约不复制**：`ingest_counts()` 内部只调用一次 `epiCore::read_counts()`，不重写契约逻辑，因此与直接调用的数值一致。
- **测试夹具现场生成**：仓库不放二进制数据，GBK、BOM、分隔符等用例在测试里临时构造。

## 已知限制

- 数据库适配器只承诺「连接 + 查询」的通用路径，不内置厂商驱动。
- HTTP 适配器不做分页、重试、限速，也不托管鉴权；需要鉴权的接口由调用方提供已签名的请求。
- 栅格只做按面聚合，不做重采样、投影转换与遥感指数。
- 脱敏覆盖地区、日期、小样本三个维度，不是差分隐私。
